# 课程模板

> 本文件规定课程的**形式**：站点分层、编号、课程页结构、动画、交互图、练习和本地动手入口。
> 课程内容、顺序和执行批次见 [`plan.md`](plan.md)。进度只记在 `handbook/status.md`。
> 规则有变化时直接修改本文件，不另建平行规范。本文件生效后，`docs/lessons/course-editorial-principles*`、`docs/lesson_delivery_policy*`、`design.md` 中与形式有关的内容以本文件为准，这些旧文件在计划批次 0 中迁移或删除。

---

## 1. 基本原则

| 原则 | 内容 |
|---|---|
| 受众 | 中文自学网站为主，同一套材料直接用于团队内部培训 |
| 语言 | **中文先行**。每一批先完成中文页并通过 review，英文页在该批验收后统一翻译 |
| 网页负责"看懂" | 静态 HTML + 无声动画（字幕）+ 预计算交互图；手机可读；不在浏览器里跑模型或拟合 |
| 本地负责"动手改" | 命令行 + Marimo，与网页使用同一套 Python 代码和产物 |
| 单一来源 | 所有数字、曲线、轨迹都来自仓库里可复现的 Python 运行；网页只读取产物，不重新实现模型 |
| 自托管 | 网页用到的 JS 库、字体、查看器全部与课程同源部署，不依赖 jsDelivr、unpkg、Colab、Hugging Face 等第三方服务 |

## 2. 站点分层

### 2.1 学员站与作者手册

| 区域 | 放什么 | 规则 |
|---|---|---|
| **学员站** `course/` | 首页、课程页、概念卡、术语表、参考书目、各课证据图与交互数据 | 只放学员读得懂、用得上的东西。不出现第 4.3 节列出的作者用语 |
| **作者手册** `handbook/` | 本模板、执行计划、进度台账、实验设计、基准规则、验证记录、路线图 | 不部署到学员站，学员页不链接进来。学员站只在页脚放一个"参与制作"链接指向仓库 |

### 2.2 目录约定

```text

  index.md                首页
  lessons/NN-slug/        每课一个目录：index.md（中文）、index.en.md（英文，后补）、assets/
  concepts/slug.md        概念卡（无编号）
  glossary.md             术语表（全站唯一）
  references.md           参考书目
  vendor/                 自托管的 JS 库与字体
handbook/                 作者手册，不部署
  template.md             本文件
  plan.md                 执行计划
  status.md               唯一的进度台账
  design/                 实验设计、基准规则等长文档
  verification/           各课验证记录
  archive/                已被取代的旧计划
sysid_lab/                Python 包：模型、仿真、拟合、产物导出、命令行
apps/                     每课一个 Marimo 文件：NN_slug.py
artifacts/NN-slug/        每课的运行产物（数据 + manifest.json），网页与本地共用
demos/manim/              动画场景与渲染结果
tests/  tools/            测试与构建工具
```

`reports/`、`synthetic/`、`notebooks/` 在批次 0 中并入 `sysid_lab/` 与 `artifacts/`。

## 3. 编号与命名

- 学员只看到一种编号：**第 N 课**，按推荐学习顺序从 01 连续编号。
- 原 K 课不单独编号：能嵌入某课的知识写进那一课；被多课反复引用的做成**概念卡**，按名称引用。
- 选修内容作为某课的"延伸"小节，或标为"选修"的独立一课；不使用 `-E`、`-O`、`-S` 这类后缀。
- 课程标题写成一个问题，例如"慢运动为什么估不准惯量？"，而不是"激励设计"。
- 路径：`course/lessons/03-excitation/`；动画 `03-excitation-<clip>.mp4`；交互数据 `artifacts/03-excitation/<name>.json`。

## 4. 课程页结构

每课回答**一个问题**。页面固定分成下列段落，标题可以改写得更自然，但顺序和职责不变。

| # | 段落 | 这一段的任务 | 必需元素 |
|---|---|---|---|
| 0 | 页头 | 让学员 10 秒内知道这课解决什么 | 眉标（第 N 课 · 主题）、问题式标题、两句导语、信息条（前置课 / 阅读时长 / 本地运行要求：无需、CPU、或 NVIDIA GPU） |
| 1 | 现象 | 先看到一个具体偏差 | 一段动画或一张图，前面有"先预测"提示框 |
| 2 | 模型与边界 | 只讲解释这个现象所需的方程 | 方程 + 符号单位表；信号表（4.2） |
| 3 | 实验 | 说清改变什么、固定什么 | 对比表：变量 / 固定项 / 拟合数据 / 留出数据 |
| 4 | 证据 | 读结果 | 动画块（第 6 节）、交互图块（第 7 节）、报告图、指标表；每项带证据标签 |
| 5 | 练习 | 学员自己做一次判断 | 2–3 题，折叠解答（第 8 节） |
| 6 | 小结 | 收束到下一个问题 | 三行固定格式："这课说明了……／还不能说明……／下一课……" |
| 7 | 动手（可选） | 本地复现与修改 | 第 10 节的固定格式 |

### 4.1 篇幅

- 正文（不含折叠解答和动手段）控制在 **15–25 分钟**阅读量；超过就说明这课在回答不止一个问题，应该拆开。
- 每段第一句就是这一段的结论或问题，不写铺垫。
- 正文中出现的数字不超过 3 个，其余放进指标表。

### 4.2 信号表

每课一张，说明每个信号能用在哪里：

| 信号 | 拟合时能用 | 只用于打分 | 只用于讲解 |
|---|:---:|:---:|:---:|
| 力矩 `u` | ✓ | | |
| 位置 `q`、速度 `q̇` | ✓（拟合数据） | ✓（留出数据） | |
| 真实参数 `J`、`b` | | ✓ | |
| 真实内部力矩 | | | ✓ |

"Oracle / Student"只在第 2 段首次出现时解释一次（真实系统 / 待辨识模型），之后正文统一用中文。

### 4.3 语气与禁用词

- 用"我们"描述一起观察，用"你"要求学员判断。
- 一个限定条件只在它限定的结论旁边写**一次**，第 6 段统一收口；正文不逐段重复免责声明。
- 实验结果还没出来时，不预写结论。
- 学员页禁用：契约、交付、评审、验收、review、runner、gate、D0x、Qxx。构建检查会扫描这些词。

## 5. 证据标签

学员页只用三种标签，放在图、动画或交互图的右上角：

| 标签 | 含义 | 何时用 |
|---|---|---|
| **运行结果** | 来自 `artifacts/` 中一次可复现的运行，数字与 manifest 一致 | 仿真输出、回放、指标、交互图 |
| **概念示意** | 为解释而画的图，不是实验输出 | 受力图、边界图、示意曲线 |
| **即将补充** | 这里将放运行结果，目前还没有 | 仅用于未完成的课 |

回放属于运行结果；只用于讲解的信号在信号表和图注里说明，不单独设标签。

## 6. 动画块

### 6.1 结构：上方文字 + 动画 + 下方文字

```html
<section class="clip-block" id="heldout">
  <p class="clip-q">固定参数后，模型能预测一段没见过的运动吗？</p>
  <aside class="predict">
    <strong>先预测</strong>
    <p>盯住蓝色虚线和黑线。如果参数只是"记住"了拟合数据，换一段输入后会发生什么？</p>
  </aside>

  <figure class="clip" data-evidence="运行结果">
    <video controls playsinline muted preload="metadata" poster="assets/02-heldout.png">
      <source src="assets/02-heldout.mp4" type="video/mp4">
      <track default kind="subtitles" srclang="zh-CN" label="中文" src="assets/02-heldout.zh-CN.vtt">
    </video>
  </figure>

  <div class="clip-read">
    <p><strong>看到什么</strong> ……</p>
    <p><strong>说明什么</strong> ……</p>
    <p><strong>不能说明</strong> ……（一句话）</p>
    <p class="clip-src">数据：artifacts/02-first-fit/heldout.json · commit abc1234</p>
  </div>
</section>
```

- 上方：一个问题 + 一个"先预测"提示，告诉学员盯住哪里。
- 下方："看到什么 / 说明什么 / 不能说明"三行，加上数据出处。
- 不再使用"阅读视频说明"折叠块，因为它只是重复字幕。
- 英文页用同一个 MP4，只换 `.en.vtt` 和上下方文字。

### 6.2 动画规格

| 项 | 规格 |
|---|---|
| 数量 | 每课 0–2 段，只给"静态图讲不清的变化过程"配动画 |
| 时长 | 15–30 秒，一段只回答一个问题 |
| 格式 | 1280×720，30 fps，H.264，单段 ≤ 1 MB，只渲染一版 |
| 结构 | 建立（坐标轴）→ 变化 → **结论定格 ≥ 3 秒**；封面取结论定格帧 |
| 背景 | 与页面一致的浅色：背景 `#f7f8f6`，墨色 `#1f2937`，次要 `#65717d` |
| 角色（全站固定，同时用颜色和线型区分） | 真实系统：墨色实线；初始模型：琥珀 `#ad7435` 实线；辨识模型：蓝 `#285f86` 虚线；残差 / 误差：珊瑚 `#c45c4d` |
| 屏幕文字 | 只允许符号（`q`、`J`、`b`、`τ`）、单位、数值、刻度。不写句子、标题和图例文字；图例由固定角色样式承担，说明放在上方 HTML |
| 字号 | 以 720p 画面计，标签 ≥ 40 px，关键数值 ≥ 48 px |
| 同屏元素 | 最多 2 个面板、3 条曲线、1 个高亮数值 |
| 数据 | 一律从 `artifacts/` 读取，禁止在场景代码里写死数字 |

### 6.3 字幕

- 3–5 条，每条显示 ≥ 3 秒，≤ 2 行，每行 ≤ 20 个汉字（英文 ≤ 42 字符）。
- **写"该注意什么、意味着什么"，不写"画面在画什么"。**
- 最后一条写结论；边界条件放到下方 HTML 的"不能说明"一行。
- 字幕中的数字由脚本生成或校验，必须与产物一致。

示例：留出验证动画的字幕改写

| 时间 | 原字幕 | 改为 |
|---|---|---|
| 0–6 s | 啁啾用于估计 J 和 b；留出的多正弦只用于评估。 | 这段输入从没参与拟合 |
| 6–10 s | 保持拟合参数固定：先出现留出位置坐标轴，再依次画出三条轨迹。 | 琥珀线：拟合前的模型，很快偏离 |
| 10–16 s | 现在三条轨迹都已画出。橙色是初始模型，蓝色辨识模型与白色真实系统重合。 | 蓝色虚线一直贴住黑线 |
| 16–21 s | 较低的留出误差支持该边界和理想观测下的预测，并非普遍保证。 | 参数学到的是规律，不只是这段数据 |

## 7. 交互图块（预计算）

交互图让学员在网页上切换条件、对比结果。所有可选组合都由 Python 事先运行好，页面只负责读取和绘制。

### 7.1 结构

与动画块相同：上方"问题 + 先预测"，中间是交互图，下方三行解读和数据出处。另外有两条要求：

- **先预测、再揭晓**：需要预测的交互图，初始状态隐藏结果；学员选择一个预测（例如"J 会估偏大 / 偏小 / 基本准确"）后才显示真实结果和解读。
- **离散选项**：控件只提供事先运行过的组合，用按钮组或吸附到网格点的滑块。**禁止在 JS 里插值或重新计算**，页面上不能出现管线从未运行过的数字。

### 7.2 规格

| 项 | 规格 |
|---|---|
| 数量 | 每课 0–2 个 |
| 组合数 | 单个交互图一般 ≤ 250 个组合；超过时减少维度或拆成两张图 |
| 数据体积 | 单页首屏加载 ≤ 2 MB；其余按选项懒加载 |
| 数据格式 | 小数据用 JSON；长数组用 Float32 二进制加 JSON 头 |
| 绘图库 | 时序图用 uPlot；等高线等二维图用 Plotly 的精简构建。全部自托管于 `course/vendor/` |
| 配色 | 与第 6.2 节角色一致 |
| 移动端 | 375 px 宽可操作；控件不依赖悬停 |
| 出处 | 下方显示产物路径与 commit（从 manifest 读取） |

### 7.3 多体与整机回放（第 09 课起）

- 3D 运动用**回放**：本地 MuJoCo / mjlab 运行后导出录制文件，网页用自托管的查看器播放（候选：Viser 静态录制、自写 three.js 回放、MeshCat 静态 HTML；批次 3 开始前做一次技术验证后选定一种，全课程统一）。
- 录制文件格式和查看器版本写进 manifest，升级查看器时统一重新导出。
- 浏览器内实时物理仿真（MuJoCo WASM）不作为默认手段。只有技术验证证明在目标手机上可用，并且不涉及控制器或拟合时，才可作为单课增强。

## 8. 练习

```markdown
### 练习 2 · 拟合很好、验证很差，先查什么？

题面：给出一张图或一组数字，学员不用运行代码就能回答。

<details><summary>参考思路</summary>

**答案**：一句话。
**依据**：指向页面上哪张图、哪一行数字。
**常见误判**：一个典型错误想法，以及它错在哪里。
**还不确定时**：回到哪一段或哪张概念卡。
</details>
```

- 每课至少一题是读图题，答案必须能从页面上的证据得出。
- 标为"即将补充"的课只出预测题，不出引用尚不存在结果的读图题。

## 10. 本地动手入口

每课固定两个入口，与网页使用同一套代码和产物：

| 入口 | 用途 | 形式 |
|---|---|---|
| 命令行 | 复现网页上的全部结果；CI 也运行它 | `uv run sysid-lab run 03`，输出到 `artifacts/03-excitation/` |
| Marimo | 学员动手改参数；培训时逐段讲解 | `apps/03_excitation.py`：自学用 `marimo run`，培训用 `marimo edit` |

- 环境：`uv sync` 一条命令安装，依赖锁定在 `uv.lock`；文档写明国内 PyPI 镜像的配置方法。
- 需要 Jupyter 的人用 `marimo export ipynb` 自行导出；仓库不维护 `.ipynb`。
- 第 09 课起可以额外提供本地 3D 查看命令（MuJoCo viewer 或 Viser）。
- 课程页第 7 段固定格式：

```markdown
## 动手试一试

运行要求：CPU 即可 · 约 30 秒

    uv sync
    uv run sysid-lab run 03          # 复现本课所有结果
    uv run marimo run apps/03_excitation.py

在应用里把激励换成"慢输入"，先预测估计会更分散还是更集中，再点击运行。
```

## 11. 数字与产物的一致性

1. **单一来源**：模型、仿真、拟合只存在于 `sysid_lab/`。网页 JS 只读取和绘图，review 时拒绝任何 JS 端的物理或拟合实现。
2. **manifest**：每次运行在 `artifacts/NN-slug/manifest.json` 中记录 git commit、配置哈希、随机种子、主要依赖版本（numpy、scipy、mujoco 等）、生成时间和每个文件的 sha256。
3. **数字注入**：正文、字幕和图注中的数字用占位符从产物渲染，例如 `{{ 03.fit.J_hat | 3 }}`。占位符缺失时构建失败。
4. **CI 比对**：CI 重跑命令行管线，在声明的容差内比对新旧产物；不一致时失败，由维护者决定是否重新生成并提交。
5. **回放版本锁定**：录制文件与查看器版本一起写进 manifest。

## 12. 双语

- 中文页是面向中文工程师的自然表达；英文页后补，不逐句对译。两边的方程、单位、数字、信号表和结论必须一致（数字都来自同一产物）。
- 术语首次出现写"中文（English）"，之后用中文。
- 术语表只有一份：`course/glossary.md`。

- [ ] 动画符合 6.2，字幕符合 6.3；交互图符合 7.2
