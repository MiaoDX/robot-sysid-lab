# 课程交付任务拆分

这是交付政策的实现待办，按依赖排序。后续实验必须先完成静态解释和本地数值路径，再开始浏览器打包。阅读页已发布不等于实验可运行或已有视频；每课单独记录可使用证据和素材状态。

## 路线 A：完成当前课程

### A1. 静态阅读审阅

- 确认无需 Marimo，L0/L1 HTML 就能说明问题、边界、拟合/验证、证据、局限和本地命令。
- 检查每个视频和报告链接。
- 加入“何时使用本地模式”说明。
- 在验证记录中保存评审地址及学员反馈。

**依赖：** 已有 L0/L1 页面与渲染短片。

### A2. 自包含 WASM 导出

- 打包本地数值模块，或为安全内联调整模块。
- 通过支持的 Marimo/Pyodide 方式声明 `numpy`、`scipy`、`matplotlib` 等浏览器依赖。
- 将所需数据/配置置于公开静态数据布局。
- 提供重复可用的导出命令；部署布局确定前，生成导出不进入源码树。

**依赖：** A1；使用已有浏览器探测验证。

### A3. 受限浏览器交互

- 每课只开放一两个适当控件。
- 时间轴、信号、数据划分只做回放选择。
- 拟合显示加载、成功和失败状态。
- 测量支持浏览器的冷启动、运行、内存及网络失败。
- 将 WASM 标记为可选浏览器实验，长任务链接到本地模式。

**依赖：** A2。

### A4. 共享静态部署

- 将课程页、视频、报告及可选 WASM 放入同一 GitHub Pages 目录树。
- 去重 L0/L1 共同的 Marimo 资源。
- 增加检查链接、资源路径和发布总大小的构建检查，无需运行 Python 计算服务。

**依赖：** A2、A3。

## 路线 B：在下一课重复流程

### B1. 选择一个受控失配问题

L1 摩擦与 L0-E 已有本地交付。按[统一课程设计](../lessons/course-design.zh-CN.md#d08)评审下一主线桥接 L1-O，L1-S 为选修。说明它相对已有 L0/L1 新增的问题，再冻结数值契约与执行预算。本待办不将可选 WASM 打包作为下一课设计或静态/本地交付的前置。

### B2. 本地基准与报告

- 实现 CPU 参考模型、冻结配置、拟合/验证数据和必要的泄漏/数值测试。
- 生成报告、指标和教学图。
- 记录完整命令与预期资源。

### B3. 静态叙事与视频

- HTML 解释新边界和省略效应。
- 为明确教学问题制作或明确延期视频；逐段标记已有、计划中或无需视频并说明理由。
- 静态页面足以让学员理解结果。

### B4. 浏览器形式决策

- 检查包支持、数据大小、时长、内存与浏览器 API。
- 明确选择：有限 WASM 拟合、WASM 回放加本地拟合，或浏览器仅静态内容。
- 在课程计划中记录决定与理由。

### B5. 本地扩展

- 实验需要时补充大数据、长优化、原生仿真器或 GPU 指引。
- 与静态及 WASM 共用实验约定。

## 路线 C：超越单刚体实验

### C1. 固定基座腿（L2）

静态/视频解释耦合与参数相关性；浏览器默认展示预计算轨迹、残差和小型回放；本地仿真负责拟合及较大数据。

### C2. 接触（L3）

静态/视频隔离接触这一新不确定性；除非小案例满足预算，浏览器只静态或回放；本地处理接触拟合和工况矩阵。

### C3. 整机（L4/L5）

静态/视频解释部件优先与全局拟合并汇总报告；浏览器浏览预计算结果；本地或调度 CPU/GPU 任务负责拟合、缓存和大数据。L4 包含已确认的小型控制器设计对比，L5 研究参数共享；L6 在同一小系统上交付结构失配与真正第二引擎两案的本地复现、静态证据/回放。范围见 [L4–L6 卡片](../lessons/course-design.zh-CN.md#l4)。

### C4. 硬件路线

HTML/视频说明安全、规程和解释；GitHub Pages/WASM 不执行硬件操作；本地工具及受控硬件服务负责采集与拟合。

## 共同验证任务

每课保留三项独立检查：

1. 仅用 HTTP 静态服务即可打开课程、证据和已有视频链接；计划中或无需视频的素材保留其声明状态。
2. 所声明的浏览器形式通过冷启动和有限交互检查，或明确无 WASM。
3. 计算实验的本地命令能够复现仓库中的报告与指标；知识/概念课没有独立数值实现时，将此项记录为不适用。

三项结果都写入课程验证文档后，任务才算完成。
