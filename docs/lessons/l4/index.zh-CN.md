# L4 · 比较整机拟合路线与控制结果

整机会让两个问题相遇：部件测量什么时候能帮助全局拟合？更好的模型是否支持下游控制任务？本课先比较工作流，再提出控制结论。

第一个整机案例使用有支撑或固定基座的 Microduck 运动。完整行走和 RL 训练是扩展，不是第一轮通关条件。

## 部件拟合良好，整机仍可能失败 {#failure}

部件优先路线可能提供有用约束，但它的假设和数据成本也会带入整机拟合。全局拟合可能拥有更多自由度、训练误差更低，却留下参数歧义。

先预测两个案例：部件约束改善留出预测；部件边界与整机不匹配，约束反而带来偏差。

## 声明 Microduck 边界 {#boundary}

使用一个主后端、一个 Microduck Oracle、紧凑 Student 参数化，以及声明的指令、关节和基座观测：

```text
指令 → 执行器/刚体/接触边界 → Microduck → 关节/基座观测
```

拟合路线本身是实验的一部分：

- 路线 A：先拟合部件、验证部件，再约束整机拟合；
- 路线 B：直接拟合紧凑的整机模型。

Oracle 真值、内部力和隐藏状态不能提供给 Student。路线 A 的额外部件数据和计算也属于它的成本。

## 先比较路线，再重新设计控制器 {#comparison}

两条路线共享整机拟合动作、留出动作族、模型选择规则和声明预算。先从有支撑/固定基座动作开始，契约稳定后再加入站立或行走。

受限的下游案例按以下步骤执行：

1. 冻结初始/辨识模型的选择规则；
2. 用同一种设计方法从每个模型生成控制器配置；
3. 在同一个 Oracle、配对初始条件和扰动上评估；
4. 分别报告跟踪、控制代价和约束违反。

辨识循环中不训练 RL。策略训练和随机化属于后续扩展，要有独立的数据来源。

## 阅读整机证据 {#evidence}

这是计划中的整机对比。路线和控制器指标只有在配对运行完成并核验后才是证据。

展示路线成本、数据来源、关节与基座误差、预测时域和参数解释，再展示两条模型到控制器的路径与配对 Oracle 评估。路线拟合损失更低，仍可能留出运动更差或参数更不可解释。

记录部件运行数量、拟合时间和约束数量，否则可能把不等数据造成的优势误报为优化器优势。

## 想一想 {#exercise}

路线 A 使用了额外执行器数据，整机拟合损失略高，但留出基座运动预测更好；它的控制器代价更低，却有一个关节的跟踪更差。哪条路线更好？

没有声明任务成本和数据预算，不能给出单一答案。分别报告额外数据/计算、留出关节/基座指标和控制器指标。只有当任务重视基座预测与代价、且约束满足时，A 才更合适；否则全局路线可能更好。不能只看拟合损失。
</details>

常见误区是按整机拟合损失给路线排名。如果还不能选择，先写出任务成本和数据预算，再比较配对的留出指标与控制器指标。当路线选择不依赖一个总分时再继续。

## 整机案例不能证明什么 {#limits}

有支撑的 Microduck 案例不能证明自由行走、硬件迁移或 RL 策略改进。只有共享且可辨识的量才有参数恢复意义。在控制器不变时，同一个 Oracle 评估也不能让离线模型比较自动变得有意义。
